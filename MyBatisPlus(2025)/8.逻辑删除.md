# 8.逻辑删除

逻辑删除是数据持久层中常用的技术方案，MyBatis-Plus 提供了开箱即用的逻辑删除功能实现

## 一、基础实现方式

### 1. 数据库准备
首先需要在表中添加逻辑删除标识字段：
```sql
ALTER TABLE user ADD COLUMN deleted TINYINT DEFAULT 0 COMMENT '逻辑删除标识';
```

### 2. 实体类配置
有两种方式配置逻辑删除字段：

#### 方式一：使用 `@TableLogic` 注解
```java
@Data
public class User {
    private Long id;
    private String name;
    
    @TableLogic
    private Integer deleted; // 逻辑删除字段
}
```

#### 方式二：全局配置（推荐）
```yaml
mybatis-plus:
  global-config:
    db-config:
      logic-delete-field: deleted  # 实体类字段名
      logic-delete-value: 1       # 已删除值
      logic-not-delete-value: 0   # 未删除值
```

## 二、功能特性

1. **自动SQL改写**：
   • 删除操作：`DELETE FROM user WHERE id=?` → `UPDATE user SET deleted=1 WHERE id=? AND deleted=0`
   • 查询操作：自动添加 `WHERE deleted=0` 条件

2. **无感知使用**：
   开发者可以像使用物理删除一样调用方法：
   ```java
   userMapper.deleteById(1L); // 实际执行逻辑删除
   ```

3. **兼容性**：
   • 支持多种字段类型：Boolean、Integer、String等
   • 默认值：已删除=1，未删除=0（可自定义）

## 三、高级用法

### 1. 查询包含已删除数据
```java
// 使用LambdaWrapper关闭自动过滤
LambdaQueryWrapper<User> wrapper = Wrappers.lambdaQuery();
wrapper.eq(User::getId, 1L).last("OR deleted = 1");
userMapper.selectList(wrapper);
```

### 2. 自定义删除值
```java
@TableLogic(value = "0", delval = "2") // 未删除=0，已删除=2
private Integer deleted;
```

### 3. 全局配置优先级
配置优先级：注解配置 > 全局配置 > 默认配置

## 四、注意事项

1. **性能影响**：
   • 所有查询都会自动添加删除条件
   • 大数据量表建议定期归档已删除数据

2. **索引优化**：
   建议为逻辑删除字段添加索引：
   ```sql
   ALTER TABLE user ADD INDEX idx_deleted (deleted);
   ```

3. **事务处理**：
   逻辑删除本质是更新操作，注意事务传播行为

4. **自定义SQL**：
   手写SQL需要自行处理逻辑删除条件

## 五、最佳实践

1. 推荐使用全局配置方式，保持统一性
2. 重要数据建议配合操作日志记录
3. 定期清理长时间（如1年以上）的已删除数据
4. 前端展示区分已删除数据状态
