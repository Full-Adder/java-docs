# Redis 内存淘汰策略详解

Redis 是一个基于内存的键值存储系统，因此内存管理对其性能和稳定性至关重要。当 Redis 内存达到限制时，它需要淘汰一些键以腾出空间给新的数据。Redis 提供了多种内存淘汰策略（也称为逐出策略），每种策略适用于不同的使用场景和需求。

## 一、内存淘汰策略概述

Redis 提供了以下几种内存淘汰策略：

1. **noeviction**：禁止驱逐。当内存达到限制时，新写入操作将返回错误。这是默认策略。
2. **allkeys-lru**：所有键使用 LRU（Least Recently Used，最近最少使用）算法进行淘汰。
3. **volatile-lru**：仅对设置了过期时间的键使用 LRU 算法进行淘汰。
4. **allkeys-random**：从所有键中随机选择一些进行淘汰。
5. **volatile-random**：仅从设置了过期时间的键中随机选择一些进行淘汰。
6. **volatile-ttl**：仅从设置了过期时间的键中选择那些存活时间最短的键进行淘汰。

这些策略可以通过配置文件 `redis.conf` 或运行时命令 `CONFIG SET` 进行设置。例如：

```sh
CONFIG SET maxmemory-policy allkeys-lru
```

## 二、各策略详解

### 1. noeviction

- **说明**：当内存达到上限时，禁止写入操作。所有写入操作将返回错误，读操作不受影响。
- **适用场景**：适用于必须保持所有数据的场景，不允许任何数据丢失。例如，缓存一些关键数据，不能因为内存限制而删除。

### 2. allkeys-lru

- **说明**：使用 LRU 算法从所有键中选择最近最少使用的键进行淘汰。
- **适用场景**：适用于一般的缓存场景，希望尽可能保留热数据，而淘汰冷数据。

### 3. volatile-lru

- **说明**：使用 LRU 算法从设置了过期时间的键中选择最近最少使用的键进行淘汰。
- **适用场景**：适用于仅希望淘汰过期数据，而不影响永久性数据的场景。例如，缓存中有一些永久性配置数据，不希望这些数据被淘汰。

### 4. allkeys-random

- **说明**：从所有键中随机选择一些键进行淘汰。
- **适用场景**：适用于简单的缓存场景，对保留哪些数据没有特别要求，随机淘汰即可。

### 5. volatile-random

- **说明**：从设置了过期时间的键中随机选择一些键进行淘汰。
- **适用场景**：适用于希望仅淘汰过期数据，但对具体淘汰哪些数据没有严格要求的场景。

### 6. volatile-ttl

- **说明**：从设置了过期时间的键中选择存活时间最短的键进行淘汰。
- **适用场景**：适用于希望尽可能保留存活时间较长的数据，而淘汰那些即将过期的数据的场景。

## 三、选择合适的淘汰策略

选择合适的淘汰策略需要根据具体的应用场景和需求：

- **缓存场景**：`allkeys-lru` 或 `volatile-lru` 是不错的选择，因为它们能有效保留热数据。
- **持久数据和缓存混合场景**：`volatile-lru` 或 `volatile-ttl` 更为适用，能保护永久性数据不被淘汰。
- **随机淘汰**：`allkeys-random` 和 `volatile-random` 适用于对保留数据没有特别要求的场景。

## 四、配置示例

在 Redis 配置文件 `redis.conf` 中配置内存淘汰策略：

```sh
# 设置最大内存使用量
maxmemory 2gb

# 设置淘汰策略
maxmemory-policy allkeys-lru
```

运行时修改配置：

```sh
127.0.0.1:6379> CONFIG SET maxmemory 2gb
OK
127.0.0.1:6379> CONFIG SET maxmemory-policy allkeys-lru
OK
```

## 五、监控和优化

监控内存使用和淘汰情况是确保 Redis 稳定运行的关键。可以使用以下命令监控内存情况：

```sh
# 查看内存使用情况
127.0.0.1:6379> INFO memory

# 查看当前的内存淘汰策略
127.0.0.1:6379> CONFIG GET maxmemory-policy
```
