# 23.ES 分页搜索
在面对大量数据查询时，我们都会使用分页，所以在使用ES时，我们不可避免的会使用到分页查询，ES为我们提供了三种分页查询的方式,我们看下
## 基于 "from/size" 的分页
这是 Elasticsearch 中最简单的分页方式。它使用 from 和 size 参数来控制在每个请求中要跳过的文档数量以及要检索的文档数量。
### 使用场景
基于 "from/size" 的分页适用于需要基本分页的情况，特别是对于小型结果集。然而，随着 from 值的增加，效率会降低，因为 Elasticsearch 需要跳过大量的文档，这可能影响性能。并且在默认情况下超过10000之后的记录，会报错

### 特殊案例
大家尝试执行如下查询，发现执行失败
```
POST example_page/_search
{
  "from": 10000,
  "size": 10,
  "track_total_hits": true
}
```
这个是因为 "from" 的值超过了默认的 index.max_result_window 设置（默认为 10000），则会导致 Elasticsearch 报错。这是出于性能和资源消耗的考虑，避免了一次性返回大量的文档。
```
{
        "type": "illegal_argument_exception",
        "reason": "Result window is too large, from + size must be less than or equal to: [10000] but was [10010]. See the scroll api for a more efficient way to request large data sets. This limit can be set by changing the [index.max_result_window] index level setting."
      }
```
那么如何解决这个问题呢：

* 第一种：按照提示解决，修改默认值大小
* 第二种: 使用后面的方式进行翻页

## 基于 search after 的分页
于 search after 的分页使用上一页中最后一个文档的唯一标识符（排序值）来获取下一组文档。这种方法可以确保在不需要跳过大量文档的情况下实现一致的分页。
### 使用场景
基于 search after 的分页在您具有可预测且唯一的排序顺序时非常有用，比如按 _doc（自然顺序）排序。它高效，并且可以用于较大的结果集，因为它不需要跳过文档，这个也是唯一的缺点，不能跳页
### 使用方式
使用这种方式，必须传入排序字段，如果mapping中没有可用于排序的字段，可以使用es的_id
```
POST example_page/_search
{
  "size": 3,
  "track_total_hits": true,
  "sort": [
    {
      "stuNo": {
        "order": "asc"
      }
    }
  ]
}
```

## 滚动分页 
滚动允许您在大型结果集上保持实时视图。它返回一个 "scroll ID"，您可以使用它来检索下一批结果。滚动会在服务器上保持搜索上下文，这可能影响资源使用。
### 使用场景
滚动适用于需要处理大型结果集而又不影响 Elasticsearch 性能的情况。它通常用于数据导出或批量处理场景。
### 使用方法
滚动翻页其实和第二种翻页有点类似，但是他第二次翻页的时候带的是返回结果中的scroll id.
* scroll=5m 代表scrollId5分钟有效，超过这个时间，缓存的资源将被回收
```
POST example_page/_search?scroll=5m
{
  "size": 3
}
```
