# 22.经常用到的的复杂查询
## 布尔查询
布尔查询用在多条件组合查询的场景中，在布尔条件中包含两类：
定义 类型介绍
#### 搜索上下文
在搜索时，ES会计算相关度得分，有一定的性能开销，包括：
##### must
包含多个查询条件，并且所有条件必须满足
##### should
不存在must和filter时，只需满足多个条件中的任意一个即可，搜索时会计算相关度得分
#### 过滤上下文
在搜索时，es只需要判断条件是否与检索数据匹配即可，不需要计算相关的分，结果在一定条件下会被缓存
##### filter
包含多个过滤条件，必须所有条件都能满足，才返回
##### must not
包含多个过滤条件，必须所有条件都不满足，才返回

#### 编写查询sql
解释下下面的sql标识的意思：
* year不能等于701
* 名字必须包含”白“
* status = true
* 年龄1300-1400之间
```
POST example_bool_query/_search
{
  "query": {
    "bool": {
      "must_not": [
        {
          "term": {
            "year": {
              "value": 701
            }
          }
        }
      ], 
      "must": [
        {
          "match": {
            "name": "白"
          }
        }
      ], 
      "filter": [
        {
          "term": {
            "status": true
          }
        }
      ],
      "should": [
        {
          "range": {
            "age": {
              "gte": 1300,
              "lte": 1400
            }
          }
        }
      ]
    }
  }
}
```
执行sql，得到的结果是这样的：：

```
          "year": 772
        }
      }
    ]
  }
}
```
你会发现其它条件都满足了，只有year这块的should没有满足，这是为什么呢？

当一个 bool 查询同时包含 must、should 和 filter 子句时，确实会出现 should 子句被忽略的情况。这是因为 filter 子句是用于非评分的过滤条件，而 should 子句是用于评分的查询条件。在 bool 查询中，filter 子句会优先被处理，不参与相关性评分，因此会导致 should 子句的评分失效。

那么如何修改sql满足我的条件呢，可以把should放到must中，作为它的bool子句，修改如下
```
POST example_bool_query/_search
{
  "query": {
    "bool": {
      "must_not": [
        {
          "term": {
            "year": {
              "value": 701
            }
          }
        }
      ],
      "must": [
        {
          "match": {
            "name": "白"
          }
        },
        {
          "bool": {
            "should": [
              {
                "range": {
                  "age": {
                    "gte": 1300,
                    "lte": 1400
                  }
                }
              }
            ]
          }
        }
      ],
      "filter": [
        {
          "term": {
            "status": true
          }
        }
      ]
    }
  }
}
```
查询结果为0，说明生效了，我们现在修改year范围(1200-1400)，看是否真的生效了,
执行后，得到我们预期的结果

## 常量得分查询
### 定义
常量得分查询（Constant Score Query）是一种特殊的查询类型，它将所有匹配的文档的相关性得分设置为一个常量值，不依赖于实际匹配的情况。常量得分查询通常用于不需要相关性评分，只关心文档是否匹配查询条件的情况。
### 使用场景
* 过滤器查询：当您只关心筛选出与查询条件匹配的文档，而不需要对搜索结果进行排序和相关性评分时，可以使用常量得分查询作为过滤器查询。

* 常量加权：常量得分查询的一个常用技巧是使用 boost 参数，通过为查询设置一个加权值，来影响搜索结果的排序。这样可以将一组文档的得分都设置为相同的值，但是在排序时根据加权值对结果进行排序。
### 使用方法
```
POST example_bool_query/_search
{
  "query": {
    
      "constant_score": {
      "filter": {
      "range": {
        "age": {
          "gte": 1000,
          "lte": 1400
        }
      }
      },
      "boost": 1.2
    }

  }
}
```

## 相关度增强查询
### 定义
相关度增强查询是一种特殊的查询方式，它旨在通过增加某些条件的权重或加分来提高文档的相关性得分。这样可以在搜索结果中优先返回那些更符合特定条件的文档，使其排在前面。
### 使用场景
* 增加特定字段的权重：对于某些字段，您可能希望它们在相关性计算中具有更大的影响力。通过增加这些字段的权重，可以让这些字段对于搜索结果的相关性得分产生更大的影响。

* 优先匹配某些条件：有时候，您可能希望文档在满足某些条件时，能够排在搜索结果的前面。例如，对于特定的标签或属性，您希望匹配上的文档排名更高。

* 个性化排序：通过相关度增强查询，您可以根据用户的个性化需求对搜索结果进行自定义排序。例如，对于某些用户，特定类型的文档可能更有吸引力，您可以通过增强相关度来优先展示这些文档。
### 使用方法
* name包含白
* year小于等于710的数据 相关性得分被乘以0.2，最终排序在最后
```
POST example_bool_query/_search
{
  "query": {
    "boosting": {
      "positive": {
        "match": {
          "name": "白"
        }
      },
      "negative": {
        "range": {
          "year": {
            "lte": 710
          }
        }
      },
      "negative_boost": 0.2
    }
  }
}
```
